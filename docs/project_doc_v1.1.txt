Introduction

1.1

Problem Context and Motivation

Autonomous path following represents a fundamental task in mobile robotics. The core challenge
addressed by this work is enabling a differential-drive ground robot (TurtleBot3 Burger) to follow
a predefined path using vision-based localization and control, without relying on GPS, SLAM, or
external odometry correction.
The key constraints are:
 Localization: fiducial marker (ArUco) detection from an overhead camera, available only
when the robot is within the field-of-view (FoV).
 Perception: path geometry extraction from camera imagery using image processing.
 Control: steering the robot to track path waypoints while respecting kinematic constraints.

This problem is relevant to industrial inspection, warehouse automation, and coordinated UAV–UGV
systems where vision-based relative localization is preferred to absolute positioning.

1.2

System Overview: UAV–UGV Architecture

The system consists of two platforms:
 Ground robot (UGV): TurtleBot3 Burger differential-drive platform, executing pathfollowing control.
 Aerial platform (UAV): stationary overhead camera providing top-down perspective for
pose and path sensing.

This architecture imposes a fundamental observability challenge: the robot can only be localized
when visible to the aerial camera. Once the robot exits the FoV, localization relies solely on wheel
odometry, which drifts unbounded without correction.

1.3

Why This Problem Motivates Uncertainty-Aware Control

Early approaches treated the system deterministically, assuming full observability and perfect state
knowledge. In practice, three factors expose this assumption as fragile:
1. Perception is intermittent: ArUco measurements are available only within the FoV. Outside
this region, the robot has no direct external feedback.
2. Sensor noise is non-negligible: both the overhead camera (marker detection) and wheel
odometry contribute measurement error. Ignoring this noise leads to overconfident control.
5

3. Dynamics are non-ideal: actuator latency, wheel slip, and sensor quantization introduce
real uncertainty. A controller that ignores these effects cannot adapt robustly when uncertainty
grows.
These observations motivate the transition from deterministic control to explicit uncertainty modeling,
formalized through belief-space control. The remainder of this document traces this evolution and
presents the resulting framework.

Path localization uses an overhead camera mounted at height h = 10 m with 60 horizontal FoV.

4. Waypoint generation: Waypoints computed in robot body frame at target distance and

2.3

Deterministic Assumptions (Early Approach)

Initial controller development assumed:
 State is fully known (no estimation error).
 Camera provides continuous pose measurements.
 Sensor noise is negligible.
 Actuators respond instantly to commands.

Under these assumptions, control reduces to a tracking problem: steer to minimize cross-track and
heading error relative to path geometry. Three controllers were explored under this framework.

Limitations of Deterministic Control

The deterministic approaches work well in controlled settings with continuous external sensing. In
practice, three critical limitations emerge:

4.1

Observability Loss Under Intermittent Sensing

The robot is localized via ArUco detection, which is available only when the robot is within the
UAV’s FoV. The FoV has a circular boundary with radius:

for h = 10 m and ϕ = 60.
Deterministic MPC plans trajectories without explicitly considering this observability boundary.
The robot can approach or exit the FoV, at which point localization fails. Once outside:
 External (ArUco) pose feedback is lost.
 Control must rely on wheel odometry alone.
 Odometry drifts unbounded without correction.
 Uncertainty in state grows without bound.

Empirical observation: Deterministic MPC occasionally approaches FoV boundaries and experiences transient localization loss, degrading control performance.

4.2

Unmodeled Noise Induces Overconfidence

Both sensors introduce real measurement noise:
 ArUco marker detection has finite precision (marker orientation estimation error ≈ 0.01 rad).
 Wheel odometry integrates motor control errors and wheel slip (cumulative drift ≈ 0.5% per
meter).

Deterministic control ignores this noise. The controller issues commands assuming perfect state
knowledge, leading to:
 Aggressive maneuvers that assume noise-free sensing.

9

 Lack of robustness when noise levels exceed assumed tolerances.
 No natural mechanism to trade off control aggressiveness for state confidence.

4.3

Actuator Lag Creates Prediction–Reality Gap

Real actuators do not respond instantly. The model includes first-order dynamics (τv = 0.5 s,
τω = 0.2 s), yet MPC still assumes these dynamics are perfectly understood and modeled. In reality:
 Motor response varies with battery voltage and load.
 Wheel slip depends on ground conditions and varies between wheels.
 Unmodeled friction and damping affect dynamic response.

Deterministic MPC does not account for the uncertainty about these dynamics. It assumes the
model is true, not approximately true.

4.4

The Need for Explicit Uncertainty Modeling

These three failures reveal a common root cause: the controller must know how much it can trust
the state estimate. This requires:
1. Quantification of uncertainty: represent state confidence as a distribution (belief), not a
point estimate.
2. Propagation of uncertainty: compute how uncertainty evolves over the MPC horizon
under control actions.
3. Observability-aware planning: choose actions that maintain observability (stay in FoV) or
actively improve state confidence.
4. Uncertainty-weighted control: penalize maneuvers that amplify uncertainty, inducing
conservative behavior when confidence is low.
This is the problem formulation of belief-space control.

5

Transition to Belief-Space Formulation

5.1

Why Model Predictive Control for Belief-Space Problems

The problem involves three key features that motivate MPC: (i) nonlinear dynamics (unicycle
kinematics), (ii) hard constraints on actuation and FoV, and (iii) future-dependent observability
(remaining in FoV is a control decision). Reactive or linear controllers cannot simultaneously
10

optimize long-term observability and tracking. Belief-space MPC addresses this by planning over
future belief trajectories, explicitly trading off immediate tracking performance for robust long-term
observability.

5.2

From State to Belief

The fundamental shift is from point-estimate state control to probabilistic belief control. Rather
than assuming a known state xk , we model uncertainty explicitly.
Belief Definition

A belief is a probability distribution over the state space:
bk = (µk , Σk ),

where µk is the mean (expected state) and Σk is the covariance (state uncertainty).
For Gaussian beliefs:
bk ∼ N (µk , Σk ).
The belief state is (5 × 1) for mean and (5 × 5) for covariance, accounting for position, heading, and
actuator states.

5.5

Observability as an Action-Dependent Property

The key insight is that observability depends on the robot’s trajectory, which is controlled.
When the robot is inside the FoV:
 ArUco measurements are available.
 Kalman update reduces covariance.
 Uncertainty can be controlled (information-gathering).

When the robot is outside the FoV:
 Only odometry is available (open-loop).
 Kalman prediction grows covariance.
 Uncertainty grows unbounded without external sensing.

Action-dependent observability: The control input uk determines the robot’s future position,
which determines future observability. MPC can choose trajectories that stay in FoV, maintaining
observability implicitly through the cost function rather than explicit constraints.

12

5.6

Solution Strategy: Belief-Space MPC

Belief-space MPC addresses this challenge by:
1. Running EKF in parallel: maintain current belief bk updated from measurements.
2. Predicting belief over horizon: for each candidate control sequence, simulate belief
propagation.
3. Costing uncertainty growth: add a penalty term λ tr(Σk ) that penalizes large covariances.
4. Optimization over controls: choose u0:N −1 that minimizes tracking error + uncertainty
cost.
The result is a controller that automatically trades off tracking accuracy for state confidence,
maintains observability implicitly, and adapts aggressiveness based on how much it trusts its state
estimate.

Implementation Architecture

7.1

System Pipeline

The belief-space system integrates perception, estimation, planning, and control in a modular ROS 2
architecture:
1. Perception: Overhead camera captures images, ArUco detection extracts pose, path segmentation extracts centerline, waypoints are generated.
2. Estimation (EKF): Fuses ArUco measurements (when visible) and continuous wheel odome17

try to produce belief state (µk , Σk ).
3. Planning (Belief-Space MPC): Optimizes trajectory over N -step horizon, predicting
belief propagation and covariance growth, using cost that penalizes both tracking error and
uncertainty.
4. Control: Executes optimal first step u0 with first-order actuator dynamics.
5. Feedback: Robot moves, new measurements arrive, cycle repeats at 5 Hz.
This architecture maintains two feedback loops: (i) standard state tracking via MPC receding
horizon, and (ii) belief-space feedback via uncertainty growth penalty.

Discussion

9.1

Why Belief-Space Control Outperforms Deterministic Approaches

The experimental results reveal the underlying mechanisms through which belief-space MPC achieves
its advantages:
9.1.1

Jacobian Coupling Drives Smooth Control

The 55% jerk reduction compared to deterministic MPC is a primary outcome consistent with the
uncertainty cost formulation. The state transition Jacobian contains the coupling:
F[0, 2] = −v sin θ dt,

F[1, 2] = v cos θ dt.

This means:
2 propagates into position uncertainty via these terms.
 Heading uncertainty σθθ

 Aggressive heading maneuvers (high ω) increase σθθ .
 The optimizer learns that such maneuvers are costly in the long term.
 Result: naturally conservative, smooth control without explicit constraints.

22

Figure 3: FoV distance and ArUco visibility over time. Belief MPC maintains larger margins to FoV
boundary and higher visibility percentage (98.3%) despite no explicit constraint.

Deterministic MPC does not explicitly penalize this coupling, typically resulting in more aggressive
heading changes. Belief-space MPC includes this cost term, contributing to smoother control.
9.1.2

Emergent FoV Awareness

Belief-space MPC achieves 98.3% ArUco visibility despite lacking explicit FoV constraints. Why?
1. Exiting the FoV causes loss of ArUco measurements.
2. Without measurements, the EKF enters pure prediction mode.
3. Predictions grow covariance unbounded (only odometry available).
4. High covariance is expensive in the cost function (λ tr(Σ)).
5. The optimizer learns to avoid trajectories that exit FoV.
This differs from hard constraints: observability is maintained implicitly through the cost of
uncertainty growth rather than explicit position penalties.
9.1.3

Modest Tracking Improvement

The 7.8% tracking error improvement over deterministic MPC is modest. Possible contributing
factors:
 All three controllers have access to the same path information and waypoints.
 Belief-space MPC uses the same planning horizon and lookahead as deterministic MPC.
 Primary advantages include control smoothness and emergent observability maintenance.
 Tracking error is constrained by path extraction accuracy and actuator limits shared across
methods.

Belief-space MPC demonstrates value in emergent behavior (smooth control, observability maintenance) alongside modest tracking improvements.
23

9.2
9.2.1

Physical Interpretation of Results
Why Covariance Traces are Comparable

The mean trace of Σ is nearly identical for Belief MPC (0.0080) and Deterministic MPC (0.0079),
yet Belief MPC achieves smoother control. This apparent paradox resolves when we examine the
mechanism:
 Deterministic MPC: High covariance evolution is not tracked or penalized. Control is
aggressive, trading some aggressiveness for tracking accuracy.
 Belief MPC: Covariance growth is penalized explicitly. The controller trades off tracking for
smoother paths that minimize future uncertainty growth.

The result is that average uncertainty is similar (both stay roughly in FoV), but the trajectory taken
to maintain that uncertainty differs. Belief-space MPC’s trajectory is smoother.
9.2.2

Why Dropout Duration Improves

When ArUco becomes unavailable (robot near FoV boundary), only odometry is available. Both
deterministic and belief-space MPC enter prediction-only mode, and covariance grows.
However:
 Deterministic MPC gets aggressively close to the boundary (1.74 s max dropout), because it
does not model the cost of exiting FoV.
 Belief-space MPC stays farther back (1.58 s max dropout), because the optimizer has already
learned that approaching boundaries is costly.

This is a learned behavior that emerges from the uncertain cost formulation over repeated optimization cycles.

9.3
9.3.1

Limitations and Scope of Results
Simulation vs. Reality

Experiments were conducted in simulation with idealized noise models and perfect actuator dynamics.
In real deployments:
 Motor response varies with battery voltage, temperature, and load.
 Wheel slip is non-negligible on certain surfaces.
 Camera calibration errors may violate the pinhole model assumption.

These factors may degrade the performance of all methods, though belief-space MPC should remain
more robust due to its explicit uncertainty modeling.
24

9.3.2

Steady-State Behavior

The 180-second runs are long enough for controllers to exhibit steady-state tracking behavior.
However, results do not show:
 Transient response to sudden disturbances or sensor failures.
 Recovery behavior after FoV loss (kidnapped robot scenario).
 Performance with dynamic obstacles or non-convex environments.

9.3.3

Optimization Landscape

SLSQP converges to local optima, which may not be globally optimal. The non-convexity arises
from:
 Trigonometric terms in kinematic integration.
 Non-convex observability function (sigmoid).
 Angle wrapping effects.

Warm-start initialization (from previous MPC solution) helps robustness but does not guarantee
convergence to the global optimum. This is a known limitation of gradient-based MPC.

9.4

What This Work Achieves

This work demonstrates a practical framework for belief-space control under FoV-limited perception:
1. Joint tracking and uncertainty optimization: belief-space MPC naturally trades off
tracking accuracy for control smoothness through the uncertainty penalty.
2. Action-dependent observability: the controller learns implicitly how to maintain observability by avoiding trajectories that grow uncertainty. No explicit FoV constraints are
needed.
3. Emergent safe behavior: uncertainty penalties alone induce conservative, smooth control
that is inherently safer for constrained platforms.
4. Robustness framework: by modeling uncertainty explicitly, the controller can adapt
its behavior based on confidence. This is a prerequisite for safe operation in uncertain
environments.

9.5

What Remains Unsolved

Five problems are explicitly beyond the scope of this work:
25

1. Global optimality: SLSQP is local; no global guarantees.
2. Multi-modal belief : kidnapped robot or ambiguous sensor scenarios not handled.
3. Active UAV planning: aerial platform is static; no coordinated planning.
4. Formal stability proofs: empirical robustness only; no Lyapunov guarantees.
5. Hard constraint satisfaction: soft penalties used; constraint violations not ruled out.
These represent natural extensions and theoretical completions of the current framework.

Perception Limitations

10.2.1

Binary Thresholding Fragility

 Fails under variable lighting (shadows, reflections).
 Requires careful tuning for each environment.

ArUco Detection Limits

Fiducial detection requires:
 Sufficient marker size and contrast.
 Fronto-parallel or near-fronto-parallel orientation (perspective distortion).
 Unobstructed line-of-sight to camera.

Heading estimation from marker orientation degrades as the robot moves away from camera center
due to perspective distortion (no correction implemented).
10.2.3

FoV Boundary Effects

At the boundary of the FoV, marker detection becomes intermittent and unreliable. In the current
implementation:
 FoV boundary is modeled as a hard circular region.
 Observability is smoothed via sigmoid for gradient computation.
 No explicit verification that marker is actually detectable outside model.

In reality, detection may fail abruptly before the model predicts it.

10.3

Estimation Limitations

10.3.1

EKF Gaussianity Assumption

The EKF assumes Gaussian noise:
wk ∼ N (0, Q),

vk ∼ N (0, R).

Violations (non-Gaussian, heavy-tailed, or multi-modal distributions) invalidate the filter. Examples:
 ArUco detection failure (not Gaussian noise, sudden loss of measurement).
 Wheel slip on certain surfaces (non-Gaussian distribution over slippage).
 Multi-hypothesis localization (kidnapped robot).

27

10.3.2

Noise Model Tuning

Process and measurement noise matrices Q and R are fixed throughout the mission. They are
empirically tuned and do not adapt to:
 Variable terrain (different friction, slip characteristics).
 Seasonal changes (lighting conditions, marker contrast).
 Sensor degradation (camera lens fouling, wheel wear).

Online noise adaptation is a recommended future extension.
10.3.3

Linearization Error Over Horizon

The EKF linearizes nonlinear dynamics around the mean. Over long horizons, linearization error
accumulates. MPC replanning (every 200 ms) helps mitigate this, but does not eliminate it for very
uncertain initial conditions.

10.4

Control System Limitations

10.4.1

Non-Convex Optimization

The MPC cost function is non-convex due to:
 Trigonometric terms in kinematic integration (sin θ, cos θ).
 Sigmoid observability function.
 Angle wrapping effects.

SLSQP finds local optima, not global. Initialization via warm-start helps but does not provide
global guarantees. This is a fundamental limitation of local optimization without convex relaxations.
10.4.2

Computational Latency

MPC optimization runs at 5 Hz (200 ms per cycle). Optimization time is typically ≈ 50 ms
worst-case, leaving time for latency and middleware delays. For faster systems:
 Compiled optimization (C++, CUDA) is needed.
 Explicit MPC (precomputed control law) would improve real-time performance.

10.4.3

No Terminal Cost

The cost function does not include a terminal penalty ϕ(xN ) at the horizon endpoint. This means:
28

 Convergence to goal (asymptotic stability) is not guaranteed.
 Very short horizons (N = 5) may not stabilize near goal.

A terminal cost or Lyapunov function would strengthen theoretical guarantees.

10.5

System-Level Assumptions

10.5.1

Static Aerial Platform

The UAV is assumed to hover at fixed position puav = (0, 0). Extensions to active UAV planning
are not addressed.
10.5.2

Obstacle-Free Environment

The path-following logic assumes a clear, navigable space. Collision avoidance with obstacles is not
implemented.
10.5.3

Sufficient Initial FoV Overlap

The system assumes the robot starts within the UAV’s FoV. If the robot and UAV do not initially
overlap in view, initialization fails (kidnapped robot scenario).
10.5.4

Vertical Camera Assumption

The camera optical axis is assumed perfectly vertical. Tilt, roll, or mounting misalignment introduces
perspective distortion that is not corrected in the current implementation.

Future Research Directions

11.1

Near-Term Engineering Improvements

Several practical extensions can improve robustness and deployability without major algorithmic
changes:
 Adaptive path segmentation: Replace binary thresholding with CLAHE (Contrast-Limited
Adaptive Histogram Equalization) or learned semantic segmentation for robustness to lighting
variations.
 Explicit angle wrapping: Implement proper angle normalization in cost function to eliminate
wraparound effects (π discontinuity) in heading error.
 Warm-start optimization: Initialize SLSQP with a shifted version of the previous MPC
solution to improve convergence and reduce computation time.
 Odometry preintegration: Cache odometry measurements between MPC updates to
improve EKF accuracy without increasing estimation latency.
 Camera calibration: Implement pinhole camera model calibration to correct for lens
distortion and improve marker detection accuracy.

11.2

Theoretical Completions

Several control-theoretic extensions would provide stronger guarantees:
 Terminal cost: Add terminal penalty ϕ(xN ) or Lyapunov function to guarantee asymptotic
stability and convergence to goal state.
 Constraint-tightening: Use robust MPC formulations (e.g., tube MPC) to provide hard
constraint satisfaction under bounded uncertainty.
 Global optimization: Employ convex relaxations (sum-of-squares, semidefinite programming)
or global solvers (BARON, Couenne) to escape local optima.
 Stability analysis: Prove closed-loop stability using Lyapunov methods or contraction theory,
providing formal robustness guarantees.
 Information-theoretic extensions: Maximize mutual information gain in addition to
minimizing tracking error (active sensing formulation).

30

11.3

Estimation Extensions

Beyond the current EKF, several estimation approaches could improve performance:
 Unscented Kalman Filter (UKF): Higher-order moment matching without explicit Jacobian computation; handles nonlinearity better than EKF.
 Particle filters: Enable non-Gaussian and multi-modal belief representations; necessary for
kidnapped robot recovery.
 Online noise adaptation: Estimate Q and R from data (e.g., using maximum likelihood)
to tune filter online rather than offline.
 Sensor fusion: Incorporate IMU, compass, or magnetic field measurements to improve
heading estimation beyond ArUco alone.

11.4

Coordinated UAV–UGV Planning

The most significant extension is active coordination between aerial and ground agents:
 Cooperative path planning: UAV plans its trajectory to maintain robot visibility and
gather information, not just hover. This becomes a coupled stochastic control problem.
 Active sensing: Use information-theoretic objectives to guide both agents toward configurations that maximize state observability.
 Distributed MPC: Both agents solve MPC problems in a coordinated manner, exchanging
intent predictions to avoid conflicts.
 Hierarchical control: UAV solves long-horizon problem (seconds); UGV solves short-horizon
tracking (milliseconds). Hierarchy enables tractable solution.

11.5

Learning-Based Augmentations

Machine learning can augment model-based components:
 Cost function learning: Use inverse reinforcement learning on expert demonstrations to
infer optimal cost weights or penalty functions rather than manual tuning.
 Path extraction: Replace floodfill with semantic segmentation networks (e.g., U-Net) trained
on diverse imagery for robust perception across environments.
 Noise model learning: Use Gaussian process regression to learn input-dependent noise
models Q(v, ω) and R(?) from data.
 End-to-end control: Train imitation learning policies to map images directly to commands,
bypassing explicit path extraction and geometric control. This is more sample-efficient than
pure RL.

31

11.6

Robustness Extensions

Handling failures and uncertainty:
 Sensor failure modes: Design controller to gracefully degrade when ArUco becomes
unavailable (odometry-only mode, slower progress).
 Wheel slip detection: Use EKF residuals to detect when wheel slip assumptions are violated;
trigger re-estimation or alert operator.
 Collision avoidance: Integrate obstacle detection and MPC-based local trajectory planning
to avoid collisions with unknown obstacles.
 Emergency maneuvers: Plan contingency behaviors (e.g., return to FoV center, reduce
speed, wait for re-localization) when state confidence drops.

11.7

Sim-to-Real Transfer

Finally, deployment to physical hardware:
 Reality gap quantification: Compare simulated vs. real sensor noise, actuator response,
and dynamics to identify and correct mismatches.
 Domain randomization: Train policies and filters with randomized parameters to improve
transfer to real hardware with unknown parameters.
 Hardware-in-loop testing: Use simulation synchronized with real sensor data to validate
algorithms before deployment.
 Iterative refinement: Collect real-world data, retune noise models, re-train learning components, and deploy iteratively.

Each of these directions represents a clear research opportunity that builds naturally on the
belief-space MPC framework developed in this work.
